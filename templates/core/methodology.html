{% translate "How this works" %}

{% blocktranslate trimmed %} Goldfish Lab does not score your deck. It plays it — shuffles, mulligans, makes land drops and casts spells, thousands of times — and reports what happened. This page says exactly what that means, and just as importantly what it leaves out. {% endblocktranslate %}

{% translate "What a goldfish is" %}

{% blocktranslate trimmed %} A goldfish is a game against nobody. There is no opponent, so there is no removal, no counterspell, no blocker and no clock. That is a limitation and it is also the point: it isolates the one question your deck can answer on its own — how reliably does it do the thing it is built to do, and by which turn? {% endblocktranslate %}

{% translate "Concretely, the engine does not model:" %}

  • • {% blocktranslate trimmed %}Opponents and interaction. Nothing is countered, killed or discarded.{% endblocktranslate %}
  • • {% blocktranslate trimmed %} Combat. Nothing attacks or blocks, so nobody takes combat damage and no creature dies. Your own life still moves: Necropotence, Dark Confidant and Phyrexian mana are paid for. {% endblocktranslate %}
  • • {% blocktranslate trimmed %} Printed keywords. Flying, deathtouch and trample are shown on a card because a person reads them. They change no number here, and we never count them as if they did. {% endblocktranslate %}
  • • {% blocktranslate trimmed %}Politics and table dynamics, which are most of what a Commander game is.{% endblocktranslate %}

{% blocktranslate trimmed %} So a deck that goldfishes beautifully can still lose every game. What this tells you is whether the deck's own plan is reliable — not whether the plan is good. {% endblocktranslate %}

{% translate "The opening hand, and how we know it is right" %}

{% blocktranslate trimmed %} A Monte Carlo simulation is only worth reading if it agrees with mathematics wherever mathematics has an answer. For the first seven cards it does: the number of lands in an opening seven follows the hypergeometric distribution, which has a closed form. {% endblocktranslate %}

{% comment %} tests/test_statistics.py, the `slow` marker. {% endcomment %}

{% blocktranslate trimmed %} The simulated distribution is checked against the exact one, computed with math.comb: the test suite draws 200,000 opening hands on every run and fails if they diverge beyond sampling error. The report used to print both side by side; it left the page because it answered a question nobody had asked, and the check did not leave with it. {% endblocktranslate %}

{% blocktranslate trimmed %} The kept hand has no exact answer, because no closed form describes it — the mulligan rule throws the tails back and reshapes the distribution. The report's "Mulligans" shows what the rule did instead. {% endblocktranslate %}

{% translate "The mulligan rule" %}

{% comment %} simulation/game.py: cards_to_bottom() is max(0, mulligans - 1). {% endcomment %}

{% blocktranslate trimmed %} London mulligan: draw a fresh seven, then put cards on the bottom. In multiplayer Commander the first mulligan is free, so the first one bottoms nothing. {% endblocktranslate %}

{% translate "A hand is kept when:" %}

  • • {% blocktranslate trimmed %}it has 2 to 5 lands; or{% endblocktranslate %}
  • • {% blocktranslate trimmed %}it has exactly 1 land and at least two cheap accelerants.{% endblocktranslate %}

{% blocktranslate trimmed %} A hand with 0 or 6 or more lands goes back. We stop after three mulligans, at five cards. {% endblocktranslate %}

{% blocktranslate trimmed %} This heuristic decides every number that follows it, which is why it is written here in full rather than described as "a sensible keep rule". It is deliberately simpler than a good player: it cannot read your hand's plan, only its shape. One consequence is worth knowing — a land-heavy deck mulligans more, not less, because forty-five lands flood into the 6+ rule far more often than twenty lands miss into the 0 rule. {% endblocktranslate %}

{% translate "The first draw, and how a turn makes mana" %}

{% blocktranslate trimmed %} In multiplayer Commander nobody skips the draw on their first turn (Comprehensive Rules 103.8c), so that is the default. Skipping it is the two-player rule, and it is there as an option for a 1-v-1 game. {% endblocktranslate %}

{% blocktranslate trimmed %} Every mana source is tapped once, at the start of the main phase: lands, mana rocks and creatures that tap for mana. A creature cast this turn is not in that pool yet, which is also what summoning sickness says - and so is a rock cast this turn, which in a real game could often be tapped at once. That second part makes the early turns read slightly lower than they play. {% endblocktranslate %}

{% blocktranslate trimmed %} A source's cost is paid: a Signet turns one mana into its two colours, so it nets one. A card that does not untap (Mana Vault) makes its mana once. One that sacrifices itself (Lotus Petal) is used once, when it lets something be cast that otherwise could not. Phyrexian mana is paid with 2 life only when the mana is needed elsewhere, and never below 25 life. {% endblocktranslate %}

{% translate "What you drew" %}

{% blocktranslate trimmed %} After every turn of every game, the engine counts the cards you have drawn so far: the opening hand you kept and each draw. A card a tutor found is not a draw and is not counted, and neither is a land a spell fetched. Cards a mulligan put on the bottom are not counted, and neither is your commander. Counting draws no random number, so the games are exactly the games they would have been without it. {% endblocktranslate %}

{% blocktranslate trimmed %} Categories — ramp, card draw, removal and the rest — come from the community's card tags, or from what you said about a card. A spell that can only fetch lands, such as Cultivate, is ramp rather than a tutor. The chart shows the share of games with at least one by each turn, because that is the question a deck is built around: do I see ramp by turn two. Card types are shown as an average count instead: almost every game sees a creature by turn one, and how many is the part that differs between decks. The mana value bars count spells only — every land is mana value zero and would drown the curve. {% endblocktranslate %}

{% blocktranslate trimmed %} The deck page's bars and filters sort the cards the same way, so a card you moved to another category moves there too. The faint band beside a bar is a common template for a hundred-card deck — about ten ramp, ten card draw, eight to ten removal, two to four board wipes, and Frank Karsten's {{ karsten_min }} to {{ karsten_max }} lands. It is a starting point many players use, not a rule, and no deck is marked for leaving it. {% endblocktranslate %}

{% translate "Reading the report" %}

{% translate "Mana and lands, turn by turn" %}

{% blocktranslate trimmed %} The median is what usually happens. The tenth percentile (p10) is the game that goes wrong — which is the one a deck gets rebuilt for, and the one an average hides completely. {% endblocktranslate %}

{% translate "What the mana was made of" %}

{% blocktranslate trimmed %} The same mana, split by colour. This is the column that says whether a mana base works: five mana on turn three is a good turn, and five mana of which four is the wrong colour is a turn spent doing nothing. {% endblocktranslate %}

{% blocktranslate trimmed %} Means, and only means — the engine's pool counts mana rather than holding the sources that made it, so a card that could have made one of several colours was read as making one fixed colour. Every card that happened to is among the cards the engine could not read, under “Cards that need your attention”. {% endblocktranslate %}

{% translate "Milestones" %}

{% blocktranslate trimmed %} The share of games in which each milestone was true by the end of that turn. They are read from the cards' own category tags, so a deck built differently gets the same chart without anything here changing. The chart draws the eight most frequent; a rarer ninth stays in the numbers under it. {% endblocktranslate %}

{% translate "What a simulation does not model" %}

{% blocktranslate trimmed %} Some limits are not bugs and more games will not fix them. They are the difference between a goldfish game and a real one, so the report names which of your cards they touch, and the field on each card that answers them. The list is read from the deck as it stands now rather than from the run: these are properties of the cards, not measurements a simulation made. {% endblocktranslate %}

{% blocktranslate trimmed %} When a card's reading is changed after a run, that run is not recalculated — its numbers are a record of what the engine actually saw — so the report says so, and running the deck again shows the difference. Magic has enormous variance: differences below about one percentage point are noise, whatever the number of games. {% endblocktranslate %}

{% translate "What the engine could not read" %}

{% blocktranslate trimmed %} Every result says how much of the deck the engine could read from the cards themselves, counting every copy: thirty Swamps are thirty of a hundred cards. A gap there is ours — a card whose text we could not turn into behaviour — and the result lists every one. {% endblocktranslate %}

{% blocktranslate trimmed %} What it counts is only that. When several spells are affordable, the engine casts the cheapest first — its own rule, not a reading of your deck's plan, with a built-in order for a few dozen well-known cards such as rituals and fast mana. We used to ask for a casting order card by card and scored decks on how much of it had been given; on the deck we measured, 161 of 217 gaps were that question, so the score mostly reported how much hand-annotation a deck had received. We stopped asking: this is a tool for statistics about a deck, not for steering a game. {% endblocktranslate %}

{% blocktranslate trimmed %} A tutor is the exception, because the cheapest card in a library is a land. A tutor takes a spell: first a piece of one of the deck's combos or a card-advantage engine, then the biggest spell it can cast by next turn. Only a search that can find nothing but lands takes a land. {% endblocktranslate %}

{% blocktranslate trimmed %} Wherever nothing could be established, the answer is a stated gap rather than a guess. A deriver that defaults a missing number is right often enough to look correct and silent when it is not. {% endblocktranslate %}

{% blocktranslate trimmed %} A card the engine could not read marks its deck red — “3 cards need you” — until you have looked at each one: correct what it reads, or say it looks right. Either way the deck turns “Ready”. Simulating never waits for it. Every value on a card's page says where it came from: {% endblocktranslate %}

{% translate "Combos" %}

{% blocktranslate trimmed %} Combos come from Commander Spellbook, looked up for your actual deck. We never guess a combo by reading card text. {% endblocktranslate %}

{% blocktranslate trimmed %} What the simulator adds is the part nobody else can: how often a combo actually comes together, and by which turn. A combo counts as assembled only when every card is in the zone the combo needs it in — on the battlefield, in the graveyard, in hand. Not "drawn", and not "seen". Measuring drawn cards would be easier and would inflate every number on the page. {% endblocktranslate %}

{% blocktranslate trimmed %} For a combo your deck is one card short of, the question is hypothetical, so we say so and measure it honestly: on a second deck that is yours plus that card, nothing cut, and the page names the card. Choosing which card your deck can spare is not a judgement this application makes. {% endblocktranslate %}

{% blocktranslate trimmed %} Expect small numbers, and read them carefully. Two specific cards in a 99-card singleton deck is about 1.6% before anything has to be cast. A result under one percent is printed as "under 1%" rather than rounded to "0%", because 0% reads as never next to a combo that did come together. {% endblocktranslate %}

{% translate "How many games is enough" %}

{% blocktranslate trimmed %} Ten thousand games gives roughly ±0.5 percentage points at 95% confidence. Past that you are buying decimal places that do not change a decision, which is why this application meters turns simulated rather than selling you iteration counts. {% endblocktranslate %}

{% blocktranslate trimmed %} A run is split into chunks across background workers. A chunked run is deliberately not bit-identical to a single run of the same seed; it replays exactly and agrees with one within sampling error, and both halves of that are asserted by tests. {% endblocktranslate %}
